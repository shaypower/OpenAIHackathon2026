## Common wire rules

- Snake_case JSON over HTTP; frontend camelCase stays behind adapters. IDs are opaque nonempty strings, stable within a dataset version. No MapLibre/runtime/agent classes cross the wire.
- API success envelopes: `{"schema_version":1,"data":...}`. Every civic result/snapshot carries explicit `data_mode`: `synthetic`, `real`, or `mixed`. `real` identifies source-backed inputs, **not verified civic findings**; evidence verification, assumptions and engine support are separate.
- GeoJSON is the exception: return an RFC-style `FeatureCollection`, with additive top-level `schema_version`, `run_id`, `data_mode`, `comparison`, `generated_at`. Do not wrap it in `data` or invent a CRS member.
- WGS84 `[longitude, latitude]` (EPSG:4326); point/line/polygon/multipolygon only in initial schemas. Stable feature IDs, closed rings, valid polygon topology and no non-finite coordinates. Domain schemas bound coordinates/shape lengths; A/B validate topology/closure and geospatial meaning at their boundaries.
- Time durations are minutes; analytical distances km; transport display edges explicitly use `distance_metres`. Operational cost is **indicative EUR/week** with method/evidence. Timestamps include date and timezone offset; source update dates may retain date-only precision. Store UTC when possible; journeys retain named timezone and original GTFS service date. Frontend formats Europe/Dublin.
- Unknown values are null with an explanation, not zero. Zero cohort means `access_percent=null` and a no-demand limitation. Never invent a finite duration for no path. Never sum household and person counts or marginal cohorts as if they were disjoint.
- Required provenance labels are never inferred from a basemap. A run with any synthetic analytical input is synthetic/mixed as appropriate; evidence involving synthetic inputs cannot be `verified` public evidence. Preserve that through export and model explanation.
- Validate input and output structurally; models reject extra fields, invalid counts/percentages and NaN/infinity. Cross-record references, feasibility, support, counts and provenance truth require owner-side checks; a DTO validation pass is not factual proof.

## Shared domain vocabulary

Read exact field types/defaults from `backend/domain/models.py`. Import examples:

| Model | Boundary and meaning |
| --- | --- |
| `Provenance` | Source/dataset/URL, known update date, actual acquisition timestamp, licence, real/synthetic, optional original record ID |
| `Evidence` | Claim + resolving provenance IDs + synthetic/unverified/verified state; no invented confidence score |
| `PopulationProfile` | Resident total, 65+ residents, no-car **households**, target-cohort residents and observed/estimated/unknown/synthetic cohort method |
| `CivicObjective` | Text, domain, service, geography/region, age/car constraints, maximum journey and optional coverage target |
| `DemandConfig` | Versioned explicit relevance/need/dependency/vulnerability weights and missing-data policy; no weighting algorithm |
| `Community`, `ServiceLocation` | Stable entities, WGS84 geography, population/service kind, provenance and data mode; service hours known flag |
| `Journey`, `JourneyLeg` | Dated, timezone-aware walk/transit/wait/transfer/service legs; feasibility and actual total or null |
| `FailureReason`, `AccessibilityResult` | Typed failure and cohort-specific deterministic access/counts; evidence/journey references |
| `Intervention`, `InterventionChange` | Proposal and explicit change parameters; **no invented pre-simulation impact** |
| `SimulationMetrics`, `SimulationRun` | Calculated results and before/after, immutable input IDs/config/engine, departure/timezone, lifecycle and evidence |
| `StressScenario` | Explicit edge/service/trip removals and display geometry; no preset percentage loss |

Only TimetableChange, FeederService and MobileService **schemas** exist now; none has backend execution. Unknown change kinds must be rejected. AdditionalDeparture, RouteExtension, NewStop and FacilityPlacement need a coordinated schema addition before execution. Keep service and journey mode extensible instead of hardcoding buses.

Semantic checks B/C must enforce: `reachable_residents <= cohort_residents`; percentage equals reachable/cohort × 100 (document rounding tolerance); chronological legs/duration totals and transfer constraints agree; duplicate IDs are rejected; referenced dataset/service/journey/evidence IDs resolve; stress IDs exist in the selected graph; terminal succeeded runs contain calculated results; failed/cancelled runs never publish a successful after-state. C retains assumptions/limitations alongside a run response. Model schemas intentionally contain no routing, ranking or provenance-verification algorithm.

## A → B/C snapshot contract

Proposed processed directory: `backend/data/processed/<dataset_id>/`. It does not exist yet. Immutable versions prevent an active run's baseline changing under it.

```json
{
  "schema_version": 1,
  "dataset_id": "synthetic-small-areas-v1",
  "region_id": "tipperary",
  "geography_vintage": "synthetic-fixture-v1",
  "data_mode": "synthetic",
  "ingested_at": "2026-10-04T12:00:00Z",
  "coordinate_system": "EPSG:4326",
  "files": {
    "communities": {"path":"communities.json","sha256":"<actual checksum>"},
    "services": {"path":"services.json","sha256":"<actual checksum>"},
    "provenance": {"path":"provenance.json","sha256":"<actual checksum>"}
  },
  "record_counts": {"communities": 1,"services": 1,"provenance": 1},
  "missing_fields": ["service_opening_hours"]
}
```

This is an example, not a generated artifact. File paths are relative to the snapshot directory, cannot escape it and must match checksums. Records in each file are arrays validating against the matching DTO. Services may be omitted until available; baseline must then report missing_data, not invent care locations. Acquisition metadata/checksums belong in the manifest, not routing code.

GTFS acquisition is a separate dated raw feed reference in the manifest/inventory with checksum, source URL/licence, valid service date range and retained agency timezone. A preserves tables/IDs; B validates service availability and builds the graph. Do not normalise GTFS into precomputed “travelMinutes” constants.

For a real `Provenance`, A must verify a genuine dataset source URL, actual acquisition timestamp, known licence or explicit licence gap, and stable record linkage. Source update date is null if unknown; preserve date-only precision instead of fabricating a time. `ingested_at` is the acquisition time, not the fixture's arbitrary authored timestamp. Inventory planned entries can have null timestamps/URL; those are not normalised records and do not validate as ingested provenance.

Inventory file format is currently implemented as `schema_version`, `inspected_on`, `real_civic_datasets_ingested`, and `sources[]`. Each entry has `id`, `name`, `dataset`, `category`, `priority`, `status`, `data_mode`, `source_url`, `source_updated_at`, `ingested_at`, `licence`, `local_paths`, and `notes`. Statuses: `PLANNED`, `BUNDLED`, `REMOTE_CONTEXT`; A may add `INGESTED`/`FAILED` only with evidence/error metadata. BUNDLED fixture/context is not civic ingestion. C's `/api/sources` must preserve these facts.

## B → C deterministic tool contract

**All functions below are PLANNED**, with a proposed public facade `backend/simulation/service.py`. Internal graph/demand types stay in B's zone. B/C should agree one concrete snapshot loader type in their handoff before implementing, rather than leaking graph internals into HTTP models.

```text
load_snapshot(dataset_id) -> validated B-owned snapshot
run_baseline(snapshot, objective: CivicObjective, departure_at, demand: DemandConfig)
  -> SimulationMetrics + AccessibilityResult[] + Journey[] + Evidence[] + MapFeature[]
find_failures(accessibility) -> failed AccessibilityResult[]
inspect_failure(snapshot, objective, result, journeys) -> FailureReason[] + Evidence[]
generate_candidates(snapshot, objective, failures, allowed_kinds, max_candidates)
  -> Intervention[]
simulate_candidate(snapshot, objective, departure_at, demand, baseline, intervention)
  -> same result bundle as run_baseline
stress_test_candidate(snapshot, objective, departure_at, demand, baseline, intervention, scenario)
  -> same result bundle as run_baseline
rank_candidates(evaluated_candidates, ranking_config_id)
  -> ordered {intervention_id, simulation_run_id, rank, score_components}[]
```

C assigns run/operation IDs and persists result bundles as `SimulationRun`; B does not own HTTP job state. Model tools are thin wrappers over these functions. `get_population` / `get_services` read A's validated records; they do not ask a model to estimate counts. Unsupported changes, invalid references, missing cohort/feed/graph and computation timeout return typed tool errors, propagated by C. C must not turn errors into quantitative defaults.

Initial cap: 20 candidate evaluations and one stress scenario per selection, within C's overall run deadline. All comparisons use identical objective, departure, dataset IDs and demand config. Ranking follows PERSON_B's explicit ordering; no hidden policy constants in routing or an LLM-assigned score.

The first candidate search preserves access for already reachable target-cohort residents. Re-evaluate impacted transfers across the scoped network before ranking; shifting one connection can break another. If future policy permits losses, report those and net gain explicitly through a coordinated metric contract rather than selecting a high-gain proposal that silently removes existing access.

### GET /api/sources — IMPLEMENTED

200 envelope: `{"schema_version":1,"data":<inventory object>}`. The nested inventory retains its own schema version. The reader loads `backend/data/source_inventory.json` on each request using a path anchored to the backend package, not the launch directory. Current readback contains 11 entries, zero real civic datasets ingested and unchanged PLANNED/BUNDLED/REMOTE_CONTEXT labels. Supported inventory statuses also include INGESTED/FAILED; these are not promoted or inferred by the API.

Response models are in `backend/api/models.py`. Unknown fields, duplicate source IDs, inconsistent real civic ingestion counts and INGESTED entries missing acquisition time/source URL are rejected. This validates metadata consistency, not dataset truth or analytical readiness. Nullable timestamps/licences are retained. Source URLs are public citations: embedded credentials and recognised credential query parameters are rejected. Local paths must be repository-relative and exclude private environment/cache/config directories.

Missing/unreadable inventory returns HTTP 503 `sources_unavailable` (`retryable=true`); malformed JSON/encoding/schema returns HTTP 503 `invalid_source_inventory` (`retryable=false`). Both use the error envelope below with a generated request UUID and empty details; responses omit file paths, invalid field values and exception text. No fallback inventory is fabricated. Additional acquisition/error fields require a coordinated DTO change rather than silently accepting arbitrary metadata.

### POST /api/objectives/validate — IMPLEMENTED (additional route)

Request: `{"text":"Make primary healthcare reachable within 30 minutes for elderly residents without cars in rural Tipperary."}`. Trimmed text is 12–500 characters; unknown/quantitative fields are rejected. Verified HTTP 200 data includes `objective: CivicObjective`, `assumptions`, `parser_mode="deterministic_template"`, `evaluable=false`, `limitations`. The supported grammar is `Make primary healthcare reachable [within <number> minutes] for elderly <people|residents> without cars in <Tipperary|rural Tipperary>.`, case-insensitive with normalised whitespace. Both wordings mean the same age-65/no-car cohort; D's actual `DEFAULT_OBJECTIVE` is checked by an HTTP regression test. Original trimmed text and explicit bound are retained. Age 65 interpretation is disclosed; omitted bound defaults to 45 with an assumption. Bounds must be >0 and ≤1440. Unsupported domain/cohort/geography or additional instructions return 422 `unsupported_objective`; invalid bounds return `invalid_objective`.

This endpoint validates intent only: it does not check snapshots/cohort availability, create runs or compute metrics. Default template mode uses no model/key. Explicit OpenAI mode supports paraphrases in the same limited scope, returns `parser_mode="openai_structured"`, and adds nullable `model_usage` (model, generation attempts, successful-attempt input/output tokens, total reserved tokens and decimal-string USD reservation). Missing time defaults to 45 with an assumption; coverage target remains null when omitted. Independent scope and numeric-bound checks accompany strict model output validation. Model mode returns public refusal/clarification errors (422) or safe provider/incomplete/usage/budget errors (503), with no automatic template fallback. Standalone validation has no request-ID replay contract and repeated model-mode requests can incur charges. Its compiler deadline is ten seconds; explicit model/rate/cost configuration is required. See AGENT_IMPLEMENTATION for setup and verification limits.

### GET /api/runs/{run_id} — IMPLEMENTED

200 data: `{"run":SimulationRun,"assumptions":[],"limitations":[],"ranking":[],"tool_trace":[],"agent_summary":null,"model_usage":null}`. D must map these additive fields. Actions contain `action_id`, `tool`, `status`, `input_refs`, `output_ref`, aware `started_at`/nullable `ended_at`, nullable `error_code`. Only actual executed actions are recorded; running traces are observable and output references appear only on success. `agent_summary` is present only for succeeded runs: run ID, `generated_by="deterministic_tool_summary"`, data mode, text, tool-reported findings (community/code/description/evidence IDs) and resolving evidence IDs. It copies recorded facts without an LLM or verification claim. `model_usage` records the compilation receipt for accepted model-mode requests, otherwise null. HTTP ranking remains empty; the tested candidate ranking library has no mounted operation yet.

Run inputs are deep-copied at acceptance and cannot change through lifecycle updates. Baseline `before` is populated only after a typed tool result passes count/percentage, aggregate scope, duplicate-ID, reference and synthetic-evidence checks. Baseline `after` remains null. Failed/cancelled jobs publish no successful metrics. Tool failure text and credentials are not returned. Lifecycle `queued → running → succeeded|failed|cancelled` is terminal; stale transitions are rejected. Shutdown cancels pending cooperative work; there is no public cancellation route.

Poll initially every 1000 ms while active, stop at terminal status or a 30-second client deadline. Network failure keeps the last snapshot with a recoverable message; do not switch to fixtures. Unknown, expired, evicted or restarted run → 404 `run_not_found`; there are no tombstones. TTL is one hour from acceptance; active records remain until terminal. At 100 runs, the oldest completed record is evicted. Its replay key expires/evicts with it, so replay protection lasts only while the run is retained. The process-local store is lost on restart and requires one worker. Browser abort stops observation only. Default production storage is empty because no backend can accept analysis yet.

Implemented envelopes cover workflow failures, HTTP errors and request-validation 422 errors (safe locations/codes, without raw input/exception context). Source/analysis dependency errors and unknown-run 404 were verified live. A registered backend can return 404 unknown dataset/config, 409 conflicting replay and 429 active-run capacity. Asynchronous execution exhaustion produces a failed run with `error_code="execution_deadline"` in a normal 200 readback, not a late change to the original 202 response. Candidate/stress routes and their specific errors remain planned.

All mutation requests require `client_request_id` (nonempty ≤160 chars). C binds it to method + normalised payload + local session/actor where applicable. Exact replay returns the original result/run; different payload is 409. Recheck uncertain request status before replay; no duplicate paid action. Public multiuser deployment/auth is outside this slice and needs explicit design; do not invent an owner identity from client fields.

Implemented local guards: one active run/process, 12 tool actions, 30-second cooperative deadline shared by analysis compilation and baseline execution, 20 candidate reservations, one refinement reservation; memory store 100 runs/one-hour TTL/single worker.
